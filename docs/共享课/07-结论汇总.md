## 二、本次新发现（公开资料中没有）

### 2.1 错误码 `-8`：学习总时长下降了

**证据：🔬**

```
① 发送 totalStudyTime=415, playTimes=540
   → 服务端存储值变为 892 = 352 + 540

② 再发 totalStudyTime=415, playTimes=540
   → {"code": -8, "message": "学习总时长下降了"}
```

**结论**：服务端算法是 **`新值 = 旧值 + playTimes`**，
且要求 `totalStudyTime` **单调不减**。

### 2.2 `learningHabitScore` 是显式配置项

**证据：🔬**

`/learning/queryStudyReadBefore` 返回的成绩规则中：

```json
{
  "usualScoreShare":           "50",
  "progressScoreShare":        "20",
  "learnedBehaviorScoreShare": "20",
  "learningHabitScore":        "20",
  "learningInteractScore":     "10",
  "finalExamScoreShare":       "40"
}
```

**"学习习惯"是一个独立的、有权重的成绩维度**，
且该接口同时返回**课程时间线**（`courseStart` / `courseEnd` / `examStart`）。

> 注：具体权重因课程与学校而异。

### 2.3 `dateFormate` 恒以 `000` 结尾

**证据：📜 + 🌐**

```javascript
Math.floor(Date.now() / 1000) * 1000
```

**先取整秒再乘 1000** → 末三位恒为 `000`。

直接用 `int(time.time() * 1000)` 会得到随机末三位，
**属于可被识别的特征差异**。

### 2.4 `questionIds` 必须是字符串

**证据：🔬**

```python
{"questionIds": [295788232, 295788233]}    # → code: -1
{"questionIds": "295788232,295788233"}     # → code: 0
```

返回的 JSON 里它看起来像数组，**实际是逗号分隔字符串**。
错误提示只有一个语焉不详的 `-1`。

### 2.5 `getMainCode()` = `uuid + "zhs"`

**证据：📜**

上报数组的第 9 个元素**不是** `uuid`，而是 `uuid + "zhs"`。
漏掉后缀会导致上报失败。

## 三、踩坑记录

按"踩坑成本"排序（**高 → 低**）。

### 坑 1 · 反混淆不处理数组旋转 ⭐⭐⭐⭐⭐

**症状**：反混淆后代码能跑，但**所有字符串都是不相干的内容**，不报错。

**为什么难发现**：混淆产物本身就不易读，
"字符串看起来莫名其妙"很容易被误判为"混淆太深，解不开"。

**正解**：用**已知锚点**反推旋转量。

```bash
node tools/anchor.mjs
# → stuStudy.js: ROT = 286（6/6 锚点一致）
# → app.js:      ROT = 140
```

```bash
ROT=286 node tools/deobf.mjs stuStudy.obf.js out.js
```

> **6 个独立锚点指向同一旋转量**，是强证据。

---

### 坑 2 · 用 CDP 抓包导致页面被销毁 ⭐⭐⭐⭐⭐

**症状**：附着 CDP 后页面白屏，`documentElement === null`。

**为什么难发现**：看起来像"网站挂了"或"网络问题"，
很难第一时间想到是**自己的调试器触发了反调试**。

**正解**：改用 **Chrome NetLog**，完全不附着调试器。

---

### 坑 3 · NetLog 的 `IncludeSocketBytes` 模式 ⭐⭐⭐⭐

**症状**：抓了一大堆数据，但**请求体全是乱码**。

**原因**：该模式记录的是**网络栈字节层**的数据，
对于 HTTPS，**body 在离开进程前就已加密** —— 拿到的是 TLS 密文。

**正解**：用 `IncludeCookiesAndCredentials`（拿头 + Cookie），
请求体则**必须靠 JS 逆向**。

> **根本认知**：**NetLog 永远拿不到 HTTPS 请求体。**
> 不要在这上面浪费时间。

---

### 坑 4 · 试图直接读浏览器 cookie 数据库 ⭐⭐⭐

**症状**：`sqlite3` 打开 `Cookies` 文件报"数据库被锁定"。

**尝试过的绕路**：

| 方法 | 结果 |
|---|---|
| 直接复制文件 | ❌ 被独占锁 |
| `robocopy /B`（备份模式） | ❌ 需要 Backup 权限，非管理员不可用 |
| 关闭浏览器再读 | ⚠️ 可行，但会丢失运行中的会话 |

**正解**：**走网络层**（NetLog），别跟数据库较劲。

---

### 坑 5 · 把 `Origin` 写成旧域名 ⭐⭐⭐

**症状**：请求被风控拦截，原因难定位。

**原因**：参考项目用的是 `studyh5.zhihuishu.com`，
**实测当前是 `studyvideoh5.zhihuishu.com`**。

**教训**：**域名会变，`Origin`/`Referer` 要跟真实浏览器对齐。**

---

### 坑 6 · 单点观察得出错误因果 ⭐⭐⭐

**经过**：

```
观察：上报值 558 > videoSec 556 之后，开始出现 -12
推断：存在"时长上限"，超限触发风控 —— ❌ 错误
```

**后续实测推翻**：服务端接受 892 > 415，无任何限制。

**教训**：**单点观察 ≠ 因果**。
必须做**对照实验**：改变一个变量，看结果是否随之改变。

---

### 坑 7 · 反调试的 `isTrusted` 检查 ⭐⭐

**症状**：程序化 `dispatchEvent` 的事件不生效，或触发风控。

**原因**：平台校验 `event.isTrusted`，
程序合成的事件该值为 `false`。

**影响范围**：只影响**浏览器自动化**方案。纯 API 客户端不受影响。

---

### 坑 8 · PowerShell 的 `Set-Content -Encoding UTF8` 写 BOM ⭐

**症状**：用 PowerShell 修改脚本后，Python 报
`SyntaxError: invalid character '\ufeff'`。

**正解**：用 `UTF8Encoding($false)`（不带 BOM），或改用 Python 写文件。

## 四、方法论沉淀

### 4.1 三种手段必须互补

| 手段 | 能给 | 不能给 |
|---|---|---|
| NetLog | 请求头、Cookie、跳转链 | ❌ 请求体 |
| JS 逆向 | 加密算法、密钥、阈值、节奏 | ❌ 服务端真实行为 |
| API 实测 | 服务端真实行为与错误码 | ❌ 客户端内部逻辑 |

**任何单一手段都不足以定论。**

### 4.2 验证闭环

```
JS 读出算法
   ↓ 用真实密文解密验证
还原出明文
   ↓ 用该算法构造新请求
服务端接受（code=0）
   ↓
结论成立
```

### 4.3 反调试的正确理解方式

> **不要问"怎么绕过反调试"，
> 而要问"反调试实现在哪一层"。**

想清楚这一点，往往**根本不需要绕过**。
